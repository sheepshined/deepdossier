# 降级行为对照表（R29：用户必须看得懂"发生了什么"）

> 本表回答一个问题：**当系统的某个环节坏了，用户在哪里、看到什么、能做什么。**
> 每种降级都在「事件流 / 报告 / 界面」三处有对应呈现。

| # | 故障场景 | 系统行为 | 事件流呈现 | 报告呈现 | 界面呈现 | 用户可做的事 |
|---|---|---|---|---|---|---|
| 1 | 问题路由分类失败 | fail-open 走完整调研 | `error`（Router）+ `route` 事件 | 无差异（正常调研报告） | 时间线红色"异常"条目 | 无需处理 |
| 2 | 主检索引擎异常/零结果 | 降级链依次尝试备用引擎 | `tool_call.engines` 显示实际引擎；主引擎缺失时发 `fallback` 事件 | 报告正常（来源来自备用引擎） | 时间线显示"命中 N 条（引擎 bing:N）"；异常时黄色"降级"条目 | 可在 `.env` 调整降级链 |
| 3 | 全链检索失败（所有引擎+MCP） | 产出"纯 LLM 知识报告" | `degraded {kind: no_web}` 事件 | 报告头部显著标注 **"⚠️ 未联网核实声明"** | 报告正文首屏可见该声明 | 检查网络后重新调研 |
| 4 | 搜索结果全被过滤判为无关 | 留底 1 条继续 | `curate` 事件显示 before→after | 该子问题进入"研究局限性" | 时间线"过滤 5→1" | 换更具体的提问 |
| 5 | 某子问题正文全部抓取失败 | 自动降级为仅用搜索摘要提炼 | `evidence_added.snippet_only=true`；抓取失败 `error` 逐条标注 | 证据卡与局限性章节注明"基于搜索摘要" | 时间线"证据 N 条" | 无需处理（质量已标注） |
| 6 | 某子问题零证据 | 缺口传入 Writer | `evidence_added count=0` | "研究局限性"章节逐条列出 | 时间线可见 | 补充提问或加轮数 |
| 7 | Critic 评审彻底失败 | 降级为"视为充分"直接成稿 | `error` + `critique.reasoning` 带 `[降级]` 标记 | 正常成稿（少了批判环节增益） | 时间线红色异常条目 | 无需处理 |
| 8 | Researcher 证据提炼彻底失败 | 该子问题空证据，其余继续 | `error`（"证据提炼失败"） | 该子问题进"研究局限性" | 时间线异常条目 | 续跑/重试 |
| 9 | Verifier 审查失败 | 放行原稿（fail-open） | `error`（Verifier） | 原稿交付 | 时间线异常条目 | 无需处理 |
| 10 | 修订输出异常缩水 | 拒绝修订，保留原稿 | `error`（"修订输出异常缩水"） | 原稿交付 | 时间线异常条目 | 无需处理 |
| 11 | 修订后引用覆盖率下降 | 放弃修订保留原稿（R19） | `error`（"放弃修订"） | 原稿交付 | 时间线异常条目 | 无需处理 |
| 12 | 引用覆盖率 <80% 且修订后仍不达标 | 交付但顶部降级标注（R21） | `quality` 事件覆盖率 <0.8 | 报告尾部 **"⚠️ 引用不充分"** 声明 | 统计行覆盖率橙色提示 | 谨慎采信，可重跑 |
| 13 | LLM 预算耗尽（次数/token/金额） | 立即终止 + 部分成果落库（R3/R27） | `error`（预算信息）+ 证据事件 | **"部分成果"报告**（已收集证据+研究计划） | 失败页显示部分成果 + 续跑按钮 | 调高预算后续跑 |
| 14 | 单 run 超时 | 取消 + 部分成果落库（R14） | `error`（超时） | 同上 | 失败页（用户语言："研究超时…"）+ 续跑 | 从断点续跑 |
| 15 | 服务重启中断 run | 启动时标记失败（F20） | 无（进程已死） | 部分成果（若有） | 失败页："服务重启导致中断"+续跑按钮（R11/R35） | 从断点续跑 |
| 16 | checkpoint 损坏 | resume 明确失败；fresh 重跑可用（R12） | run 失败事件 | 无 | 失败页提供"放弃断点重新跑" | 二选一恢复 |
| 17 | 并发打满 | 任务排队不崩溃（R15） | run 创建后事件延迟出现 | — | 创建响应 `queued:true`，时间线显示"排队中 N/M" | 等待自动开始 |
| 18 | 事件写库失败/磁盘满 | 内存缓冲重试，run 继续（R16）；启动时磁盘检查告警 | 事件延迟落库（seq 不变） | 无差异 | 无感知（可能事件延迟） | 清理磁盘空间 |
| 19 | 单次 LLM 调用过慢 | 超阈值发事件（R28），流程继续 | `slow_node` 事件（schema/耗时） | 无差异 | 时间线"调用"条目可见 | 无需处理 |
| 20 | 导出（HTML/DOCX）生成失败 | 降级返回原始 Markdown + 错误说明（R20） | 无 | — | 下载内容头部为"导出失败说明" | 直接复制 Markdown |
| 21 | MCP 数据源调用失败 | 跳过该源，web 结果兜底 | `error` + 服务日志 warning | 报告正常（web 来源） | 时间线引擎分解不含该 MCP | 检查 MCP server 配置 |

维护约定：新增任何降级行为时**必须**同步本表（代码 PR 的验收项之一，对应 R29/R40）。
