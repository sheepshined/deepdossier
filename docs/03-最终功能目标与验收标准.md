# DeepDossier 最终功能目标与验收标准

> 本文档定义 DeepDossier 的**最终交付形态**：产品应具备的核心功能、特性表现与可衡量的质量标准。
> 不考虑实现难度与成本，只回答一个问题——**什么样的 DeepDossier 才算"做完了、做好了"**。
>
> **2026-09-13 更新**：新增第 5–7 章——对照本文档 F1–F25 的逐项验收结果、发现的问题清单（含优先级）与下一步优化计划。

## 0. 产品定位（一句话）

输入一个复杂问题，系统通过多 Agent 协同（多视角拆解 → 并行检索 → 对抗性批判循环 → 带引用写作），产出一份**逐结论挂引用、经批判检验、矛盾显式呈现**的调研报告，全程可观测、可断点恢复、免 key 可离线演示。

## 1. 核心功能目标

### 1.1 智能研究流水线（核心价值）

| # | 功能要求 | 衡量标准 |
|---|---|---|
| F1 | **问题智能路由**：闲聊/简单询问由快模型直接回答，复杂问题才进入完整研究流水线；路由失败时一律走研究（fail-open） | 简单问候不进流水线、不消耗检索资源；分类异常不产生错误中断 |
| F2 | **多视角问题分解**：Planner 将复杂问题拆解为多个子问题，每个子问题带 perspective 视角标注，视角之间不重复 | 默认产出 3–5 个子问题；子问题数上限可配（默认 5）；同类问题拆解结果视角差异化 |
| F3 | **并行证据采集**：每个子问题独立完成「搜索 → 来源质量筛选 → 抓取正文 → 产出证据卡（事实要点 + 来源 + 置信度）」，子问题之间并行执行 | 并行扇出而非串行；每条证据卡含来源 URL 与置信度字段；抓取失败不阻断整体流程并在事件中标注 |
| F4 | **来源质量过滤**：搜索结果在抓取正文前经轻量模型做相关性筛选（curation） | 功能可开关（默认开）；筛选失败时保留原始结果（fail-open）且至少留底 1 条 |
| F5 | **对抗性批判循环**：Critic 对照研究计划审查全部证据，输出证据缺口、来源矛盾与定向补搜查询；证据不充分则触发定向补搜，直至充分或达到轮数上限 | 补搜轮数上限可配（默认 2 轮）；每轮批判结论结构化（gap / contradiction / follow-up query）；达到充分条件即终止循环 |
| F6 | **矛盾显式呈现**：Critic 发现的来源冲突必须传入 Writer，在报告中以独立章节呈现 | 报告含「争议与不确定性」章节；存在矛盾时不得静默吞掉 |
| F7 | **带引用报告**：Writer 按子问题组织报告，逐结论挂编号引用 `[n]`，引用按 URL 去重、编号重排并与正文同步改写 | 正文每个事实性结论均有引用支撑；引用列表无重复 URL；编号连续无断号；支持中/英文报告（默认中文） |
| F8 | **策略记忆（跨 run 学习）**：每次研究结束后沉淀 1–2 条搜索策略经验，注入未来同类问题的 Planner | 记忆支持中文模糊匹配（n-gram）与语义检索（embedding 余弦）双模式可配；配置 embedding 模型后自动切换语义检索 |
| F9 | **研究深度可控**：用户可指定研究深度（depth）、子问题数、补搜轮数等参数 | CLI 与 API 均支持参数透传；run 参数持久化，断点续跑时自动恢复 |

### 1.2 数据源与检索能力

| # | 功能要求 | 衡量标准 |
|---|---|---|
| F10 | **可插拔检索器**：支持 DuckDuckGo（默认免 key）、360 搜索（国内网络免 key）、Bing、Tavily、Serper、Stub（离线） | 环境变量一键切换，不改代码 |
| F11 | **检索降级链**：主检索器异常或零结果时，按配置的降级链依次尝试备用检索器 | 降级链可配（逗号分隔）；降级过程在事件中可见 |
| F12 | **MCP 数据源接入**：支持标准 `{"mcpServers":{...}}` 配置的 MCP 数据源（stdio / http 传输），作为检索补充挂在降级链尾 | 领域工具支持多步调用链；web 结果与 MCP 结果合并去重 |
| F13 | **混合并行检索**：带关键词的领域 MCP 源按查询词选择性并行补充 | 并行补充不拖慢主链路；结果合并去重 |

### 1.3 输出与交付形态

| # | 功能要求 | 衡量标准 |
|---|---|---|
| F14 | **CLI 三命令**：`research`（执行研究并输出报告文件）、`serve`（启动 Web 服务）、`demo`（零 key 离线演示） | 三条命令开箱可用；`demo` 在无任何 API key 的干净环境跑通全链路 |
| F15 | **报告多格式导出**：Markdown 原文件、独立 HTML（单文件、打印即 PDF）、Word .docx（真实超链接、上标引用、表格） | 三种格式均从同一 run 导出；docx 引用为上标可点击超链接 |
| F16 | **Web 时间线可视化**：零构建单文件前端，实时展示 Agent 协作时间线（SSE 推送），含历史 run 列表、来源面板、报告导出与失败续跑入口 | 打开首页即可发起研究并实时观看各节点事件；断线重连后事件不丢失（回放补齐） |
| F17 | **REST API**：创建研究任务、查询状态/报告、SSE 事件流、导出、断点续跑 | 全部端点文档化；事件序列号（seq）单调递增可回放 |
| F18 | **Python API**：可作为库被其他 Python 项目直接调用 | 提供示例脚本（examples/），import 即用 |

### 1.4 可靠性与企业级能力

| # | 功能要求 | 衡量标准 |
|---|---|---|
| F19 | **断点续跑**：研究中断（崩溃/超时/服务重启）后可从最近检查点恢复，不重头再来、不重复扣预算 | 事件 seq 从历史最大值续接；恢复后报告完整产出 |
| F20 | **任务治理**：后台并发上限（默认 4）、单 run 硬超时（默认 600s）、优雅关停（进行中任务取消并落终态） | 超限任务排队而非崩溃；超时任务状态正确标记；重启后无"僵尸运行中"状态 |
| F21 | **成本控制**：单 run LLM 调用次数硬预算（默认 150）、token 用量/成本统计、快慢双模型分工 | 达到预算立即终止并落终态；用量统计可在 run 详情中查看 |
| F22 | **API 安全**：所有 `/api/*` 端点（含 SSE）可选 X-API-Key 鉴权（常量时间比较），CORS 可配，创建任务令牌桶限流（按 key/IP，默认 10 次/分） | 未配置 key 时开放；配置后无 key 请求一律 401；限流触发返回 429 |
| F23 | **存储治理**：SQLite（WAL）存储 runs / events / lessons / embeddings；保留策略（按天清理 runs/events、按量封顶 lessons）在服务启动时自动执行 | 保留天数与条数可配；清理不影响进行中任务 |
| F24 | **Provider 无关**：一个 `base_url` 切换 DeepSeek / GLM / OpenRouter / Ollama / vLLM 等任意 OpenAI 兼容端点 | 切换仅改环境变量；结构化输出失败自动修复重试一次 |
| F25 | **全程可观测**：每个节点发射结构化事件（node_start / node_end / llm_call / tool_call / evidence_added / critique / final / error / done），三通道落地——SQLite（恢复+回放）、JSONL trace 文件（自托管追踪）、Console（CLI 实时显示）；结构化日志 | 任一 run 可完整回放事件流；trace 文件按 run_id 独立成文 |

## 2. 质量标准（验收线）

### 2.1 报告质量

| 标准 | 验收方式 |
|---|---|
| 报告结构完整：摘要、按子问题组织的正文、「争议与不确定性」、引用列表 | 任一真实 run 产出报告人工检查四要素齐全 |
| 引用覆盖率 100%：每个事实性结论都有 `[n]` 引用，无"裸结论" | 抽查报告逐段核对 |
| 引用无重复 URL、编号连续，正文编号与列表一致 | 自动校验（引用合并逻辑已实测修复 39% 重复来源，目标趋近 0 重复） |
| 经批判循环的报告在事实覆盖度上显著优于单轮检索（对比单轮 RAG 基线） | 同一问题两种模式对比评审 |

## 3. 最终形态的边界（明确不做什么）

- **不做框架**：DeepDossier 是应用型产品，不抽象为多 Agent 开发框架
- **不引入重型基础设施**：不依赖 Celery/Redis/向量数据库即可完整运行（进程内 asyncio + SQLite 足够，接口预留扩展点）
- **不绑定单一 LLM 或搜索厂商**：任何厂商锁定都视为缺陷
- **不依赖外部可观测平台**：tracing 自托管（JSONL），不强制接入 LangSmith 等第三方服务
