# 竞品调研与选型（2026-09）

> 调研范围：GitHub 上多 Agent 协同方向的 6 个代表性高分项目，覆盖「应用型」与「框架型」两类。
> 结论先行：**做应用型项目「深度调研智能体 DeepDossier」**，框架型赛道不进入。

## 1. 候选项目总览

| 项目 | Stars | 类型 | 定位 |
|---|---|---|---|
| [TradingAgents](https://github.com/TauricResearch/TradingAgents) | ~104k | 应用 | 多 Agent 金融交易决策框架 |
| [MetaGPT](https://github.com/FoundationAgents/MetaGPT) | ~70k | 框架 | SOP 驱动的"AI 软件公司" |

## 2. 逐项分析

### 2.1 TradingAgents（架构最佳借鉴对象）

**架构**：LangGraph 状态图。4 个分析师（基本面/情绪/新闻/技术）并行 → 多空研究员结构化辩论（轮数可配）→ 交易员决策 → 风控团队辩论 → PM 审批。

**技术栈**：Python + LangGraph；LLM Provider 抽象覆盖 OpenAI/Claude/DeepSeek/Qwen/GLM/Ollama 等；SQLite checkpoint 断点恢复；决策日志 + 反思记忆（上次决策的实际收益回灌进下次 prompt）。

**优点**：
- 「并行专家 + 对抗辩论」是报告/决策质量的核心来源，被论文和社区反复验证
- 反思记忆闭环，系统越用越准
- 工程成熟：多 Provider、checkpoint、CLI、Docker 齐全

**缺点**：
- 深度绑定金融领域与行情数据源，不可复用
- 输出是单一交易决策，不是可阅读的调研报告

**吸收**：总体编排骨架（并行→辩论→汇总→审批）、反思记忆机制、Provider 抽象与 checkpoint 思想。

### 2.2 GPT-Researcher（同赛道产品化最佳）

**架构**：Planner Agent 生成研究问题 → 多个 Execution Agent 并行爬取 → 逐源摘要 + 来源追踪 → 过滤聚合 → Publisher 出报告。另有 Deep Research 递归树状探索（深度×广度）与 LangGraph 多 Agent 版（研究组+发布组）。

**技术栈**：Python + FastAPI + NextJS/静态前端；默认 Tavily，支持多 retriever 与 MCP 数据源；LangSmith / Monocle 观测；pip 包 + Docker。

**优点**：
- 并行化好，速度快；"多站点交叉验证降低偏差"的理念清晰
- 产品化程度最高：前端、PDF/Word 导出、MCP、pip 分发
- 文档与社区成熟

**缺点**：
- **没有对抗性批判环节**——靠"多站点投票"降偏差，单一视角的系统性盲区无法消除
- 默认与 Tavily 强绑定；代码层体积大，二次开发成本偏高

**吸收**：并行执行 Agent 模式、来源追踪与引用规范、FastAPI + 轻量静态前端的部署形态。

### 2.3 STORM（同赛道学术最强）

**架构**：两阶段——Pre-writing（视角引导提问 Perspective-Guided Question Asking + 模拟"作家×专家"对话收集参考文献 + 生成大纲）→ Writing（按大纲成文并带引用）→ Polish。Co-STORM 扩展为多专家 + 主持人圆桌 + 动态 mind map + 人在环。

**技术栈**：Python + dspy 模块化；litellm 多 Provider；retriever 插件化（Bing/Serper/SearXNG/DuckDuckGo/Tavily 等 10+）。

**优点**：
- 「多视角提问 + 模拟对话」是搜索深度的学术级答案（NAACL/EMNLP 论文）
- 模块接口定义干净，可定制性最强

**缺点**：
- dspy 学习曲线陡，运行成本高
- 输出形态单一（百科长文），前端简陋

**吸收**：Planner 的多视角子问题分解（perspective 字段）、双模型策略（快模型跑模拟/慢模型写成文）。

### 2.4 MindSearch（可视化最佳，但已停维护）

**架构**：WebPlanner 把问题拆成 DAG 子查询，WebSearcher 分层检索，模拟人类思维；React 前端可视化图求解过程。

**优点**：DAG 并行子查询；**执行过程可视化是出圈关键**；中英文双语。

**缺点**：2024 年后基本停更；深度有限；绑定 InternLM 生态。

**吸收**：子问题 DAG 思想、前端实时展示 Agent 协作时间线。

### 2.5 OpenAI Agents SDK（SDK 设计最佳）

**核心概念**：Agent = instructions + tools + guardrails + handoffs；agents-as-tools（把 Agent 当工具调用）；sessions 自动历史管理；内置 tracing。

**吸收**：Agent 间 handoff 语义、全链路 tracing 的落地方式（我们做自托管 JSONL trace，不依赖 LangSmith）。

### 2.6 MetaGPT / ChatDev（框架型，仅参考范式）

SOP 角色流水线 + 消息订阅总线。开创了"角色分工"范式，但面向代码生成、框架重，二次开发成本高。**不进入框架赛道的决策依据**：MetaGPT/CAMEL/Microsoft Agent Framework/OpenAI SDK 已占据心智，应用型项目（TradingAgents 104k）涨星速度远超框架型。

## 4. 选型结论

**做「DeepDossier 深度调研智能体」**：输入一个复杂问题，输出一份带引用、经过批判循环检验的调研报告。

差异化定位（对竞品的"取长补短"）：
1. **GPT-Researcher 的并行 + 产品化形态**，补上它缺失的 **TradingAgents 式对抗批判循环**
2. **STORM 的多视角分解** 融入 Planner，避免子问题同质化
3. **TradingAgents 的反思记忆** 做成 SQLite 策略记忆，跨 run 学习搜索策略
4. **MindSearch 的过程可视化** 做成 Web 时间线（SSE 推送 Agent 事件）
5. **企业级工程底座**：多 Provider、免 key 搜索、自托管 tracing、断点事件存储、Docker、测试与 CI
