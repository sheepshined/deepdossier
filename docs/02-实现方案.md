# DeepDossier 实现方案

> 一句话：输入复杂问题 → Planner 多视角拆解 → Researcher 并行检索 → Critic 批判循环 → Writer 带引用报告，全程事件可观测、可断点恢复。

## 1. 系统架构

```
                    ┌──────────────────────────────────────────────┐
                    │                FastAPI / CLI                 │
                    │   POST /api/researches   GET /events (SSE)   │
                    └───────────────┬──────────────────────────────┘
                                    │ Deps(provider, retriever, sink, store)
                    ┌───────────────▼──────────────────────────────┐
                    │            LangGraph StateGraph              │
                    │                                              │
                    │   START ──► planner ──► researcher ×N ──►    │
                    │                 ▲   (Send 并行扇出) │        │
                    │                 │                   ▼        │
                    │                 └────── critic ◄────┘        │
                    │            (缺口→定向补搜, ≤N轮)   │          │
                    │                        sufficient ▼          │
                    │                     writer ──► END           │
                    └──────┬───────────────┬───────────────┬───────┘
                           │               │               │
                  ┌────────▼─────┐  ┌──────▼──────┐  ┌─────▼─────────┐
                  │ LLM Provider │  │ Retriever   │  │ EventSink     │
                  │ OpenAI 兼容  │  │ DDG/Tavily/ │  │ SQLite+JSONL  │
                  │ /Stub        │  │ Serper/Stub │  │ +Console      │
                  └──────────────┘  └─────────────┘  └───────┬───────┘
                                                             │ SSE
                                                      ┌──────▼──────┐
                                                      │ Web 时间线   │
                                                      └─────────────┘
```

**Agent 编排（借鉴来源标注）**：
- **Planner**：多视角拆解问题为 3-5 个带 perspective 的子问题（借鉴 STORM 视角引导），注入策略记忆中的历史经验（借鉴 TradingAgents 反思记忆）
- **Researcher × N**：LangGraph `Send` 并行扇出，每个子问题：搜索 → 抓正文 → 产出 EvidenceCard（事实要点+来源+置信度）（借鉴 GPT-Researcher 并行执行 + 来源追踪）
- **Critic**：对照计划审查证据，输出缺口/矛盾/定向补搜查询；不充分则回到 Researcher 定向补搜，最多 N 轮（借鉴 TradingAgents 辩论机制）
- **Writer**：按子问题组织报告，逐结论挂引用 `[n]`，输出 Markdown
- **Memory**：run 结束后沉淀 1-2 条搜索策略经验，供 Planner 检索复用

## 2. 技术栈与选型理由

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.10+（实测 3.13） | 生态主力，竞品一致 |
| 编排 | **LangGraph** | 状态图原生表达"并行 Send + 条件循环"；TradingAgents/GPT-Researcher 同款；比自研调度省 1000+ 行且可 checkpoint |
| LLM 接入 | **openai SDK**（base_url 可换） | 一个客户端覆盖 DeepSeek/GLM/OpenRouter/Ollama/vLLM；结构化输出用 prompt-JSON + pydantic 校验 + 修复重试（兼容所有国产模型） |
| 搜索 | **可插拔 Retriever**：DuckDuckGo（默认免 key）/ Tavily / Serper / Stub | DDG 免 key 是开箱即用关键；Stub 支离线测试与演示 |
| 网页抓取 | httpx + BeautifulSoup | 轻量；trafilatura 作为后续增强 |
| API | FastAPI + SSE | 竞品一致；SSE 比 WebSocket 简单可靠，天然适合事件流 |
| 存储 | SQLite（标准库） | 运行记录/事件/记忆/报告零运维；后续可换 Postgres |
| 配置 | pydantic-settings + .env | `DOSSIER_` 前缀环境变量，12-Factor |
| CLI | typer + rich | 企业级 DX |
| 测试 | pytest + pytest-asyncio | StubProvider/StubRetriever 全链路无网络测试 |
| 部署 | Docker + docker-compose | 标准交付 |

**刻意不引入**：LangChain 全家桶（只取 langgraph）、向量库（MVP 不需要）、Celery/Redis（进程内 asyncio 足够，接口预留）。

## 3. 关键设计

### 3.1 状态与归约
`ResearchState`（TypedDict）：`evidence` 用 `operator.add` 归约器承接并行写入；`round`/`pending_queries` 由 Critic 单点写入避免竞态；`ctx` 相关内容不进状态，通过 `Deps` 闭包注入。

### 3.2 结构化输出
所有 Agent 输出走 pydantic 模型（ResearchPlan / EvidenceCard / Critique）。LLM 调用统一 `complete(system, user, schema=...)`：JSON 模式失败时带错误信息重试一次（国产模型常见，必须有修复环）。

### 3.3 事件与可观测
节点内通过 `deps.emit(run_id, type, node, payload)` 发事件：
- `node_start / node_end / llm_call / tool_call / evidence_added / critique / final / error / done`
- 三个落点：**EventWriter 后台线程批量写 SQLite**（断点恢复+SSE 回放）、`traces/{run_id}.jsonl`（单句柄、自托管 tracing）、Console（CLI 实时显示）
- SSE 采用「EventHub 即时通知（事件落库回调 call_soon_threadsafe 唤醒）+ SQLite 回放（断线重连）」双通道，不再盲轮询

### 3.4 任务治理（v0.2 新增）
- TaskManager：后台 run 强引用防 GC、信号量并发上限、单 run 硬超时、服务关停时取消并落终态
- API 令牌桶限流（按 key/IP）；`MAX_LLM_CALLS` 单 run 调用预算
- 存储保留策略：runs/events 按 `RETENTION_DAYS` 清理，lessons 按 `MAX_LESSONS` 封顶（启动时执行）

### 3.5 企业级清单
- 多 Provider + 重试退避 + token 用量/成本统计 + 单 run 调用预算
- API 可选 `X-API-Key` 鉴权（常量时间比较，覆盖全部 `/api/*` 含 SSE）；CORS 可配
- 结构化日志（`deepdossier.*` logger 层级）；Docker 健康检查
- pytest 全离线全链路（MockTransport 断网断言）；ruff lint；CI 含 Docker 镜像 Web UI 回归
- 免 key 离线演示（Stub 双件套）

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 国产模型 JSON 输出不稳定 | 修复重试环 + temperature=0.3 + pydantic 严格校验 |
| DDG 限流/被封 | Retriever 插件化，Tavily/Serper 一键切换 |
| 抓网页反爬/编码乱码 | UA 伪装、超时熔断、失败跳过并在事件中标注 |
| LangGraph API 变动 | 锁定版本下限；编排逻辑集中在 builder.py 单文件 |
| 成本失控 | 用量统计 + max_subquestions/rounds 上限 + 快慢双模型 |

## 10. v0.3 更新记录（2026-09-12）

在 v0.2 架构上的增量，不改变核心编排：

- **开头问题路由**：START → router →（direct: 闲聊/简单询问由快模型直答，不进检索流水线 | research: 原流水线）。fail-open：分类失败一律走 research。教训：LangGraph 状态新增键必须在 `ResearchState` TypedDict 声明，否则静默丢弃。
- **来源质量过滤**：researcher 在抓取正文前用快模型对搜索结果做相关性筛选（`source_curation`，fail-open + 留底 1 条），GPT-Researcher 式 curation。
- **检索降级链与混合并行**：`FallbackRetriever`（主引擎异常/零结果依次降级）+ `HybridRetriever`（带 keywords 的领域 MCP 按查询词选择性并行补充，web/MCP 结果合并去重）。
- **MCP 数据源**：`tools/mcp_source.py`，兼容标准 `{"mcpServers":{...}}` 配置（stdio/http 传输、cwd）；领域工具用 `call_chain` 多步调用，参数支持 `{query}`/`{prev}`/`{"$llm":"提取指令"}`。
- **断点续跑**：AsyncSqliteSaver 每超级步落 checkpoint；失败 run 经 `POST /api/researches/{id}/resume` 恢复，事件 seq 从历史最大值续接；run 参数（max_rounds）持久化于 `params_json` 并在续跑时恢复。工程注意：aiosqlite 连接与事件循环绑定，必须每次 run 独立开关。
- **导出**：`/export`（独立 HTML，打印即 PDF）与 `/export.docx`（python-docx，真实超链接/上标引用/表格）。
- **引用合并**：Writer 输出按 URL 去重、编号重排并同步改写正文 [n]（实测修复 39% 的重复来源）。
- **工程**：FastAPI lifespan 迁移、限流器桶清理、run 参数持久化、测试资源关闭（90 项全离线测试）。
